# МК — сайт «Курси + Магазин»

Next.js 16 + Payload CMS 3 в одному застосунку, PostgreSQL, розгортання на Vercel.

Бриф, кошторис і решта внутрішніх матеріалів у репозиторії **не зберігаються** —
вони лежать поруч із ним і додані в `.gitignore`.

## Важливо: диск

Репозиторій має лежати на **NTFS**. Робоча копія — `C:\Users\Taras\dev\magazin_markame`.

З exFAT (диск `E:`) проєкт не працює:

- Turbopack не може створити junction point і падає (`os error 1`);
- у режимі `--webpack` псується dev-кеш, RSC-потік обривається на
  `SyntaxError: Unexpected end of JSON input`, і сторінка рендериться, але не
  «оживає»: кошик і вибір варіацій мовчать, помилок у консолі при цьому нема.

## Запуск

```bash
# 1. База даних і сховище файлів
docker compose up -d

# 2. Оточення
cp .env.example .env      # PAYLOAD_SECRET згенеруйте самі

# 3. Залежності й демо-дані
npm install
npm run seed              # адміністратор, напрями, курси, товари, відгуки
npm run seed:content      # сторінки, журнал, апсел до наборів
npm run storage:sync      # створює бакет у сховищі
npm run seed:photos       # 29 фото з seed-assets/ у медіатеку

# 4. Сервер
npm run dev
```

MinIO: вебінтерфейс на http://localhost:9001 (`mkadmin` / `mkminio123`).

Сайт — http://localhost:3000, адмінка — http://localhost:3000/admin
(`admin@mk.local` / `mk-admin-2026` після сідування).

> Відкривайте саме `localhost`, а не `127.0.0.1`: Next віддає 403 на клієнтські
> чанки для адрес поза `allowedDevOrigins` — сторінка при цьому виглядає
> нормально, але не реагує на кліки. Обидві адреси прописані в `next.config.ts`.

## Структура

```
src/
  app/(frontend)/    сайт: головна, магазин, курси
  app/(payload)/     адмінка та REST/GraphQL API Payload
  collections/       модель даних: товари, варіації, курси, замовлення…
  components/site/   шапка, бічне меню, кошик, картки
  components/admin/  дрібні компоненти адмінки
  lib/, fields/      форматування, медіа, слаги
  seed/              демонстраційне наповнення
```

## Оплата й видача доступу

Шлях: кошик → `/checkout` → `POST /api/checkout` → форма WayForPay →
колбек `POST /api/payments/wayforpay/callback` → `fulfillOrder()`.

- **Ціни й залишки перераховуються на сервері** (`lib/orders.ts`). Кошик у
  браузері — лише перелік бажаного, суму з нього не беремо.
- Колбек приймається тільки з валідним HMAC-MD5 підписом, відповідь теж
  підписується — інакше WayForPay повторює запит.
- `fulfillOrder` ідемпотентна: повторний колбек не спише залишок удруге.
- Без `WAYFORPAY_*` у `.env` замовлення все одно створюється зі статусом
  «очікує оплати» — видно в адмінці.
- Без `TELEGRAM_BOT_TOKEN` видача інвайтів просто пропускається, без падінь.
  Бот має бути адміністратором каналу з правом створювати запрошення.
- Без `NOVA_POSHTA_API_KEY` підказки адрес вимикаються, поля вводяться вручну.

## Файли

Медіа зберігаються в **S3**, а не на диску застосунку — інакше на Vercel вони
зникали б після кожного деплою. Локально ту саму роль виконує **MinIO** з
`docker-compose.yml`: він сумісний з S3, тому при переїзді на AWS S3 чи
Cloudflare R2 змінюються лише значення `S3_*` у `.env`, код лишається той самий.

Файли віддаються через `/api/media/file/<імʼя>`, тож бакет може лишатися
закритим — публічна політика доступу не потрібна.

`npm run storage:sync` створює бакет і переносить у нього все, що лежить у
локальній теці `media/`. Записи в базі зберігають лише імена файлів, тому після
перенесення з тими самими ключами нічого правити не треба.

## Двомовність

Українська в корені (`/shop`), англійська з префіксом (`/en/shop`) — основний
ринок не платить редіректом за мову, яку додають на майбутнє. Дерево сторінок
одне: `middleware.ts` переписує `/en/*` на `/*` і кладе мову в заголовок запиту.

- `lib/i18n.ts` — словник інтерфейсу й `localePath()`;
- `components/site/LocaleLink.tsx` — заміна `next/link`, яка тримає відвідувача
  в його мові. Внутрішні посилання по всьому сайту йдуть саме через неї;
- сторінки запитують контент у Payload з `locale` поточного запиту.

Інтерфейс перекладено повністю — шапка, підвал, кошик, каталог, сторінки
товару й курсу, оформлення, кабінет, відгуки, журнал і пошук. Словник — у
`lib/i18n.ts`.

Лишається наповнити **англійський контент** у Payload: поля локалізовані, але
англійських значень у базі немає, тож доки їх не заповнять, спрацьовує запасний
варіант і показується українська. Переклад текстів клієнтки в кошторис не
входив.

## Що вже працює

- **Магазин**: каталог із фільтрами (категорія, колір, наявність, сортування),
  сторінка товару з вибором варіації та обмеженням за залишком, набори з
  можливістю докупити дрібницю, пошук.
- **Курси**: напрями, сторінка курсу з програмою МК, покупка у два кліки,
  автоматична видача доступу, безтерміновий доступ у кабінеті.
- **Оформлення**: Нова Пошта й Укрпошта, промокоди, накладений платіж із
  передплатою, WayForPay, фіскальні чеки Checkbox.
- **Кабінет**: вхід листом або паролем, «Мої доступи» з повторною видачею,
  збережені курси.
- **Контент**: журнал, статичні сторінки з адмінки, відгуки з модерацією.
- **Маркетинг**: підписка на розсилку, розсилки з адмінки (пошта + Telegram),
  лист про кинутий кошик, GA4 і Meta Pixel зі згодою на cookie, мікророзмітка,
  sitemap, robots і картинка для соцмереж.
- **Адмінка**: українською, генератор варіацій колір × розмір, шаблон таблиці
  для завантаження товарів (`/api/admin/products-template`).
- **Інструкція для клієнтки**: `ІНСТРУКЦІЯ.md`.

## Кошик між пристроями

Кошик живе в базі (`carts`), а не лише в браузері. Анонімний тримається на
токені в httpOnly-cookie, після входу привʼязується до облікового запису й
зливається з тим, що людина набрала до входу — не перезаписує, а саме зливає.

Назви, ціни й залишки підставляє сервер: кошик, який пролежав тиждень, не
покаже стару ціну або зниклий товар.

> Синхронізація між пристроями працює **після входу в кабінет**. Без нього
> сервер не може знати, що телефон і ноутбук — одна людина.

## Домовленості в коді

- Ціни форматуються в `lib/format.ts` вручну, **не** через `Intl.NumberFormat`:
  Node і браузер ставлять різні пробіли перед «₴», через що ламається гідратація.
- `priceFrom`, `inStock`, `totalStock` у товарах рахуються хуком при збереженні —
  щоб фільтри працювали запитом до бази, а не в памʼяті.
- Списання залишків іде в транзакції з блокуванням рядка (`decrementStock`):
  без нього два одночасні замовлення останньої одиниці проходять обидва.
- Словник `lib/i18n.ts` містить функції, тому передавати його пропом із
  серверного компонента в клієнтський не можна — клієнтські компоненти беруть
  мову через `useLocale()` і збирають словник самі.
- У масивах Payload не можна називати поле `order`: конфліктує зі службовою
  колонкою порядку.
